### Notes

- **All 8 repos are affected** — none are unaffected.
- `rng` auto-renames = 0 across all repos because none of the repos use variables named `rng` / matching `/[Rr]ng$/` and none use `createRng`/`restoreRng` in their `src/`. The rng-flagged "review" column covers the 9 RNG call sites found whose receivers were not identifiable by the conservative heuristic (e.g. an rng stored as `this.rand` or passed through a typed parameter — these are `rng-review` entries).
- `step-split` = 0 everywhere because none of the consumers currently call no-arg `.step()` directly; they use `startLoop`.
- `error-match` = 0: none of the consumers directly construct `DomecsError` — they consume errors from the engine API but do not build them.
- `studio` has 1 `world-review` entry (a World method call in `main.ts` whose receiver was a parameter of non-`world`-named type; the codemod conservatively flagged it rather than silently editing).
- The `railroad_game` has the highest auto-edit density (18 auto-edits in `railroad.ts` alone — it is the most API-heavy consumer).

### Out-of-scope repos

- **`domecs_template_vite`** — pins published `^0.1.0-alpha.0` (not source-linked via `file:` dep), so it is **not** part of the lockstep migration set. It will pick up changes when a new published alpha is tagged.
- `halls_game`, `harbor_game`, `prism_app`, `hypernovasystem.github.io` — not in the v1.0 lockstep set as listed in the task spec.
