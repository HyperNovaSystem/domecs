## DOMECS v2.2.0

All seven `@domecs/*` packages at 2.2.0. An additive minor: the first half of the behaviour language for data-defined sims (cross-entity rules, a spatial index, world expressions, input in rules), plus act-log recording, replay and branches for the Studio AI harness. `^2.0.0` peer ranges still resolve. Specification: [`doc/harness/2026-10-18-harness-engine-gaps.md`](../harness/2026-10-18-harness-engine-gaps.md) §5, §7.1, §7.2 and §8.

### Highlights

- **Rules can see other entities.** Selectors `first(S)`, `nearest(S[, d])` and `entity(n)` read `e.Component.field` and `e.id`. `has([e,] C)`, the aggregates `count`, `exists`, `sum`, `avg`, `minOf` and `maxOf`, and `countWithin(S, r[, e])` and `distanceTo(e)` cover the rest. `a ?? b` gives a fallback when a value is missing: a missing field, an empty selector, a dead `entity(n)` or an empty `avg`. New functions: `sqrt`, `pow`, `atan2`, `hypot`, `sign`, `round`, `ceil`, `lerp` and `distance`. `RuleDef.without` excludes components. Pass `installRules(..., { spatial: { component, cellSize } })` before using the spatial forms. A chase behaviour is now one rule with no host code: `atan2(first(Player).Pos.y - Pos.y, first(Player).Pos.x - Pos.x)`.
- **More deterministic maths.** `dmath.atan2`, `dmath.hypot` and `dmath.pow` give bit-identical results in every ECMA-262 engine. `atan2` and `hypot` are musl ports and `pow` is an fdlibm port. Rules use them automatically.
- **A spatial index.** `createSpatialGrid(cellSize)` in `@domecs/core` is a pure 2D grid: `within`, `nearest` and `pairs` return the same results as a brute-force scan for any cell size or insertion order, and ties go to the lowest id. `@domecs/scene` `createSpatialHash(world, { component, cellSize })` indexes one position component and supports tag filters. It is derived state and never snapshotted.
- **World expressions.** `compileWorldExpression(source, resolve)` compiles a rule expression that has no evaluated entity, for metrics, probes and outcome checks (`countWithin(Enemy, 40, first(Player))`). `evaluate(world)` returns a `Result` and is read-only: it does not draw randomness, does not move change windows, and leaves the strict hash and `describe()` unchanged.
- **Input in rules.** `key(n)`, `pressed(n)`, `released(n)`, `mod(n)` and `pointer.x|y|buttons|wheel` read the tick's `world.input`, so player control can be written as data. Edge reads (`pressed`, `released`, `pointer.wheel`) are compile errors in `fixed` rules, because an edge lasts one render tick.
- **Record and replay.** `createRecorder(world, { hashEvery })` records everything that reaches a world from outside — acts, input, scale and dt — as a plain-JSON `ActLog` (`format: 'domecs-actlog'`, `version: 1`) with strict-hash checkpoints. `replay(world, log, { base })` re-runs the log on a fresh build of the same setup and reports `diverged` at the first checkpoint that differs. A direct out-of-tick write is recorded as a gap, not passed over silently. `encodeInput` / `decodeInput` give `InputSnapshot` a JSON form.
- **Branch and compare.** `createBranch(setup, snapshot, { fixedStep, scale })` builds a fresh headless world from a snapshot without touching the live world or its views. `runBranch(world, { steps, probes, log, until, shouldStop, keyframeEvery, hashEvery })` steps it and returns samples, keyframes, strict hashes and faults. Runs are synchronous and can be extended, so a host can run them in a worker and cancel them. This replaces the plantroom pattern of restoring and stepping the live world.
- **`validateEventPayload` is public.** It is the schema check that `world.action()` and `bridge.act()` apply, exported so hosts can pre-validate a command without emitting it.
- **The fork-equivalence suite covers 2.2.** A live world edited mid-run and running chase rules (spatial, input, own streams, acts through `emit` and `action`) is matched tick for tick over 150 steps by three continuations: a fresh build restored from its snapshot, a fresh build replaying its act log, and a branch run over that log. The dual-runtime golden adds rules fixtures for `first`, `nearest`, `countWithin`, `atan2`, `hypot` and `pow`. Its output is identical under Node and Electron 44.9.0 run as node.

### Behavior changes

- **Reserved words in rules.** `self`, `tick`, `other`, `event` and `pointer` are reserved, and so is `id` after an entity. A component with one of these names can no longer be referenced in an expression: it is a parse error ("reserved word") at the name. `key`, `pressed`, `released` and `mod` are not reserved: only a call reads input, so `key.x` is still `Component.field`.
- **`a??b` now lexes as `??`.** It used to be a syntax error.
- **Component names are resolved at compile time everywhere,** including the new sets and `has` targets. A missing self field still faults the entity, now as a "no value" error (still a `RuleEvalError`).
- **`restore` keeps registered component types.** After a restore, `describe().componentCounts` lists every registered type, with 0 for a type that no restored entity holds. Before, such a type was dropped until the next read of it. Snapshots and hashes are unchanged.
- **`action()` / `bridge.act()` reject inherited keys.** Payload validation now checks own properties only. A key that exists only on `Object.prototype` (`constructor`, `toString`, or `__proto__` produced by `JSON.parse`) is an undeclared field and is rejected. Before, it was accepted.
- **`createBranch` needs the source's `fixedStep`.** A snapshot carries `fixedStep` only while a fixed backlog is pending, so pass `live.time.fixedStep` (and the scale) explicitly. This is not a change from 2.1, since branches are new, but it is easy to miss.

Snapshots are unchanged: still format v3, with no new fields, so 2.1 and 2.2 read each other's saves. The 2.1 golden fixtures and hashes are byte-identical in 2.2.

### Type-level changes

- **`FunctionName` widens.** `FUNCTION_NAMES` gains nine names, and `FUNCTION_ARITY` gains their keys. An exhaustive `switch` over `FunctionName` needs a case for each new name or a default branch.
- `AstNode` gains `member`, `entityId`, `has`, `aggregate`, `countWithin`, `distanceTo`, `nullish`, `input` and `pointer` nodes. `identifier.name` gains `'tick'`.
- `RuleDefPath` gains `{ without: number }`. As the 2.1 notes said, keep a default branch when you switch on it.
- `EvalEnv` gains the optional `input` hook.

Code that does not switch exhaustively over these unions compiles unchanged.

### New APIs

- `@domecs/core`:
  - spatial grid: `createSpatialGrid`, `SpatialGrid`;
  - deterministic maths: `dmath.atan2`, `dmath.hypot`, `dmath.pow`;
  - record and replay: `createRecorder`, `replay`, `encodeInput`, `decodeInput`, and the types `ActLog`, `ActLogFrame`, `ActRecord`, `ActLogGapReason`, `Recorder`, `RecorderOptions`, `ReplayOptions`, `ReplayError`, `JsonInput`;
  - branches: `createBranch`, `runBranch`, and the types `WorldSetup`, `BranchOptions`, `BranchError`, `RunBranchOptions`, `BranchRun`;
  - validation: `validateEventPayload`.
- `@domecs/scene`: `createSpatialHash`, and the types `SpatialHashOptions`, `SpatialIndex`.
- `@domecs/rules`:
  - world expressions: `compileWorldExpression`, `WorldExpression`;
  - rule analysis and options: `walkComponentRefs`, `SPECIAL_FORMS`, `InstallRulesOptions.spatial`, `compileRule`'s optional `{ spatial }` argument;
  - types: `EntityNode`, `AggregateOp`, `SpatialOption`, `CompileRuleOptions`, `InputOp`, `PointerField`, `ModifierName`.

The full signatures are in [`doc/api-surface/`](../api-surface/) and [`doc/api.md`](../api.md). `doc/api.md` has a runnable doctest for each new API.

### Upgrading from 2.1.0

1. Upgrade all `@domecs/*` packages to 2.2.0 together. The packages' `@domecs/core` peer range is now `^2.2.0`: `@domecs/scene` needs `createSpatialGrid` and `@domecs/rules` needs the new `dmath` functions.
2. Rename any component called `self`, `tick`, `other`, `event` or `pointer` that rules reference. Rules that use these names now fail to compile with "reserved word", so `RulesHandle.update()` or `compileRule` reports them.
3. Add a default branch to any exhaustive `switch` over `FunctionName`, `AstNode['kind']` or `RuleDefPath`.
4. If a host calls `world.action()` with payloads built by `JSON.parse` or by an agent, expect inherited keys such as `__proto__` and `constructor` to be rejected as undeclared fields.
5. Optional, for agents and tools:
   - Record sessions with `createRecorder` and verify them with `replay`.
   - Answer "what if" questions with `createBranch` + `runBranch` rather than restoring the live world. Pass the source's `time.fixedStep` and `time.scale`.
   - The AGENTS.md recipes "Record and replay" and "Branch and compare" show both.
   - Hashes and goldens recorded on 2.1 stay valid.
