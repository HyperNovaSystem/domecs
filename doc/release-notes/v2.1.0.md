## DOMECS v2.1.0

All seven `@domecs/*` packages at 2.1.0. An additive minor: the determinism foundation and build identity that the Studio AI harness builds on. `^2.0.0` peer ranges still resolve. Specification: [`doc/harness/2026-10-18-harness-engine-gaps.md`](../harness/2026-10-18-harness-engine-gaps.md) §4 and §8.

### Highlights

- **One answer to "is this the same state?"** `hashSnapshot(snap, { includeChanges: true })` hashes a canonical form of the snapshot: keys sorted, `-0` kept, non-finite numbers rejected. `canonicalJson` serializes snapshots for disk without losing `-0`, and `@domecs/persist` `diffSnapshots(prev, next, { fields: true })` and `firstDivergence(a, b)` show which field moved.
- **The same numbers in every runtime.** `dmath.sin` / `dmath.cos` are a port of musl libm and return bit-identical results in Node, Electron and browsers. `Math.sin` / `Math.cos` differ between V8 builds; on one linux-arm64 host, Node 24 and Electron 44 disagree on them. Rules use `dmath` automatically.
- **Edit one rule without reshuffling the others.** With `rng: 'own'` (on a system, a rule or `installRules`), each system draws from its own stream, keyed by name and derived from the world seed. The streams travel in the snapshot.
- **A fork matches the live world.** `installRules(..., { order: 'stable' })` makes a rule's run position depend only on the doc, not on when `update()` ran. `snapshot({ pendingEvents: true })` carries events emitted but not yet delivered, so a fresh build restored from a live snapshot continues on exactly the live world's path. A new fork-equivalence suite checks this for 150 ticks after edits.
- **Names agents can resolve.** `world.register(...types)`, `lookupComponent` / `lookupEvent` / `lookupResource`, `eventTypes()`, name-based `AgentBridge.act(name, payload)`, and a richer `describe()` (per-system `priority`, `order`, `components`, `meta`, `rng`; field and event `description`).
- **Rule errors point at the field.** `RuleError.field` names the part of the def an error is about (`'when'`, `{ action: 1, part: 'expr' }`, …).
- **Build identity.** Every package exports `BUILD_ID`. `scripts/pack-for-studio.mjs` packs build-stamped tarballs (`2.1.0+g<sha>`) and a manifest for hosts that consume unpublished builds.
- **Dual-runtime golden.** `pnpm test:golden` runs `scripts/determinism-golden.mjs` (fixed worlds using trig, the shared stream, own streams and a `-0` bounce) and compares its output with a committed golden. With `DOMECS_ALT_RUNTIME="env ELECTRON_RUN_AS_NODE=1 /path/to/electron"`, it also requires identical output under that runtime.

### Behavior changes

- **Snapshot format v3.** `SNAPSHOT_VERSION` is 3, and every snapshot a 2.1 world writes has `version: 3` and a `rngRoot`, even when no system uses own streams or pending events. **A 2.0 engine rejects a 2.1 save** ("newer than this engine supports"). 2.1 still restores and loads 2.0 saves: a v2 snapshot restores onto the world's `createWorld` root, and `@domecs/persist` migrates 2 → 3 in memory. `hashSnapshot` leaves out `version` but includes `rngRoot`, so the hash of a world-built snapshot changes once.
- **`sin()` / `cos()` in rules may change by ≤ 1 ulp.** They now evaluate with `dmath`, not `Math.sin` / `Math.cos`. A sim that uses them may produce results that differ from 2.0 by at most 1 ulp in a given runtime, so its hashes change once. From then on its results are the same in every runtime.
- **"Same state" now means equal strict hashes.** Canonical JSON keeps `-0`, so two snapshots that differ only in the sign of a zero now compare unequal. They can have different futures (`1 / v`, `Math.sign`). Compare `hashSnapshot(…, { includeChanges: true })`, not `JSON.stringify(snapshot())`. `@domecs/persist` `save()` still serializes with `JSON.stringify`, which writes `-0` as `0`.
- **`diffSnapshots` compares component data, not JSON text.** An entity whose components differ only in key order is no longer reported as changed. One whose field went from `0` to `-0` now is.

### Type-level changes

None that break 2.0 code. `RuleDefPath` (new) is documented to widen in later minors, so keep a default branch when switching on it.

### Upgrading from 2.0.0

1. Upgrade all `@domecs/*` packages to 2.1.0 together.
2. If a 2.0 deployment still reads saves that 2.1 writes, upgrade it first: a 2.0 engine rejects v3 snapshots. 2.1 reads 2.0 saves unchanged.
3. Any hash or golden recorded from a world-built snapshot changes once (`rngRoot`; `sin`/`cos` in rules). Re-bless it once on 2.1, after a review.
4. Determinism checks: compare `hashSnapshot(snap, { includeChanges: true })`, and serialize keyframes or forks with `canonicalJson` (lossless `-0`). In hand-written authoritative systems, replace `Math.sin` / `Math.cos` with `dmath.sin` / `dmath.cos`.
5. Optional, for forks and A/B comparisons: install rules with `{ order: 'stable', rng: 'own' }`, and take fork snapshots with `snapshot({ pendingEvents: true })`. Before restoring, register every event type that can be in flight (`world.register(...)`).
